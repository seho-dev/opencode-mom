# Mini Island Native Service

## Overview

macOS-only capsule window, cached IPC state, and one cancellable OpenCode SSE task. Disabled by default; disabling destroys the window and clears local private data, never interrupts sessions or rejects requests.

## Structure

- `mod.rs`: managed `IslandService`, immutable `Arc` snapshots copied outside the cache lock, shared explicit `IslandView`, generation-guarded requests, event coalescing, reconnect and shutdown.
- `window.rs`: macOS public `NSScreen` safe-area discovery, public window policy, main-thread-local native transition slot and `NSAnimationContext`/`NSWindow.animator()` frames with completion readback; no runtime class replacement or global input monitors.
- `transition.rs`: pure serial/generation/native-window identity guards, one active/latest pending lifecycle, duration selection and final-frame verification.
- `hover.rs`: public `NSTrackingArea` with a separate main-thread owner for non-key hover, weak notification/cache references, window-lifetime teardown and pure tracking-policy tests.
- `geometry.rs`: pure bounded compact/peek/expanded frames and shared finite frame acceptance in AppKit logical coordinates, with geometry tests.
- `tests.rs`: explicit view wire contract, native transition lifecycle/readback guards, stale-response exclusion, private-cache clearing, task abortion, async action-lifetime cancellation, dual synthetic-backend IPC epoch rejection and actual queued-request cancellation.

## Conventions

- Persist `state.islandEnabled` outside `AppPreferences`; acquire `models::config_write_lock` around config read/modify/write.
- Connect through the shared local target transport (default Shared or fixed explicit loopback V2, never explicit fallback/bootstrap). `set_enabled` acquires the target transition mutex inside native main dispatch, not while awaiting it. Target transactions take `prepare_target_refresh()` under that mutex before persistence; dropping `TargetRefresh` leaves state unchanged, while post-commit `invalidate()` clears private snapshots/API/selection and cancels old lifetimes without changing enabled/preferences/view/notch metadata. Disabled refresh is a no-op. Call `finish_target_refresh(app, generation)` only after releasing the target mutex; its native dispatch reacquires the mutex and generation-checks before reconciliation/restart. A missing window reports a safe Refresh-repair error without opening, disabling or persisting preferences. A finalization error must not fail an already-committed target save. Async reads and pre-write dispatch check captured target revision.
- Failed window setup returns an error, clears runtime enablement and persists the safe disabled default. Open rejects any still-registered `island` label before native setup: queued destruction never permits reuse or tracking reinstallation. Remain disabled on rejection; explicit enable can retry after runtime destruction removes the label, without automatic retry or waiting. Repeated enable of an already-active window remains a no-op. Readback never claims a missing window was created. Explicit Refresh while enabled without a current API replaces the monitor immediately, including initial connection/error states, with no session writes.
- Never hold cache locks across awaits, AppKit/window calls, or event emission. The task captures cache data and a weak notification slot owned by the run loop, never its own service or a permanent `AppHandle`.
- Monitor replacement and shutdown serialize task ownership before checking/updating cache generation; abort/spawn runs outside the cache lock. A stale finalizer cannot replace or abort the current monitor. State exposes required camelCase `connectionGeneration` directly from the cache generation so frontend data lifetimes also reset across equal session IDs.
- Subscribe before snapshot. Only SSE invalidations trigger coalesced snapshots; reconnect delays are 1/2/5/10 seconds. No full snapshot polling or disabled watchers.
- `island_messages` records the selected session only while expanded. Message SSE for other sessions or collapsed views is ignored; collapse/disable clears selection. The first eligible invalidation owns the fixed 250 ms deadline, never extended by subsequent tokens; Snapshot flushes publish before notifying.
- SSE is live-only with no replay; every reconnect subscribes anew and rebuilds the snapshot. Publish snapshots and connection errors only while the generation matches under the cache lock.
- Actions require a current enabled API and a separate action-lifetime watch token installed with each accepted API. Fail/replacement/stop/reconnect invalidate the API and cancel/drop the old action token under the same cache lock; connection failures do not cancel the monitor's SSE retry lifetime. Mutation-lock waits and the entire action future (including fresh GET before POST) race action cancellation, with generation guards before/after execution. Mutations are serialized and never automatically retried. Cancellation drops local work but cannot withdraw an already-issued POST.
- Messages and all five action IPCs require unsigned `expectedConnectionGeneration` from the originating state; no omitted/current-generation fallback. `request(expected, action, mutation)` and `messages(session_id, expected)` reject stale generations under the cache lock before cloning API/cancellation context, starting reads/actions or changing selection, including when the new backend reuses session/request/form IDs. Only internal explicit Refresh may capture the current context without an expected generation; view commands are unchanged.
- Emit only empty `island:changed`/`island:collapsed`/`island:pointer-enter`/`island:pointer-leave` events to `island`; state/preferences reads are cache-only. Initialize preferences from app config once and update the cache inside successful preference persistence before emitting notifications.
- View is explicitly `compact` (default on every screen), `peek` or `expanded`; pending snapshots, connection/status changes and refresh never choose a view. Compact is `max(notchWidth + 112, 200)` by `max(topInset, 28)`, peek is `400` by `topInset + 132`, expanded stays `560` by `520`. Clamp every mode to screen bounds with the same top/notch-center anchor; clamp edge-notch compact width symmetrically to keep its content-free notch safe gap aligned. The UI paints a continuous black backdrop, not a transparent notch cutout. No-notch screens retain the menu-bar fallback and show richer compact text without enlarging. Compact/peek clear selected messages, never pending requests.
- `set_island_view { view }` is async internally with the same lowercase enum-to-void wire contract. Capture enabled generation before `on_main`, which starts the operation and returns a `tokio::sync::oneshot::Receiver`; await only outside the native main thread/cache/TLS borrow. Grow keeps the old authoritative cache view until final native readback succeeds. Only the still-current explicit expanded request focuses; peek never focuses or orders front. Compact requests and authoritative blur/close immediately compact the cache, clear selection and emit empty `island:collapsed`, before any shrink and without session writes.
- One main-thread-local slot owns one active request and only the latest pending request. Each captures enabled generation, monotonically increasing serial and native pointer/window number. Pending replacement resolves the displaced request with a safe superseded error; active supersession allows the current animator to finish but excludes its readback, success, focus and rollback. Rapid reversal deliberately waits at most the current approximately 220 ms animation. Register active before entering AppKit, whose completion may be immediate. Completion releases only its own token; stale callbacks cannot clear a new active token or touch replacement windows. Disable/close/destruction invalidate/drop both receivers; a per-window weak destruction listener captures native identity rather than trusting the reusable label. Reconnect invalidates results and receivers while retaining an active animator until completion, then reconciles the authoritative view instantly. Never hold cache locks or TLS `RefCell` borrows across native calls, emissions, callbacks or awaits.
- Animate changed view sizes with public `NSAnimationContext.runAnimationGroup_completionHandler` and `NSWindow.animator().setFrame_display(frame, true)` (`RcBlock` completion): grow 0.22 s, shrink 0.19 s. Completion on the main thread performs origin correction and final readback before geometry commit/focus/resolve/changed emission. No immediate final readback after a legacy `setFrame_display_animate`, overlapping animator, timer, observer, runtime class replacement or animation framework. Startup, unchanged frames, display placement and current `NSWorkspace.accessibilityDisplayShouldReduceMotion()` use the existing instant path; query Reduce Motion for each transition, without a watcher. Real native bounds continue to control `InVisibleRect` hover and hit testing, with no permanent expanded invisible area.
- Changed/SSE/message notifications are generation-guarded content emissions only, not placements. Moved/focus events during an active transition never correct intermediate frames or start another animator; actual screen-placement/DPI changes set one dirty bit for instant reconciliation after the active animation. Idle move/DPI/focus correction is instant and never focuses. Explicit expanded focus can reenter `Focused(true)` without recursively resizing. Unchanged native frames are not rewritten; message notifications never fetch a snapshot. Notifications never order front or focus.
- AppKit calls stay on the native main thread. Use public safe-area selectors only when present; fallback below the menu bar.
- Initial display uses public `NSWindow.orderFront`, not Tauri `show()` (which makes macOS windows key); focus is requested only by explicit expansion.
- Install one `NSTrackingArea` on the content view with `ActiveAlways | InVisibleRect | MouseEnteredAndExited | MouseMoved`: WebKit's own overlay-scrollbar tracking can be key-window-only. Its separate `NSObject` owner only emits pointer notifications; it never focuses, changes view, reads the API or performs actions. Visible-rect tracking follows real resized bounds. Repeated moves notify only compact to recover missed entry; ordinary peek sends only boundaries. Retain owner/view/area in main-thread-local storage and detach before releasing the owner on replacement, close, shutdown and destroyed events. Weak cache/notification handles avoid service/AppHandle cycles; ignore disabled/expanded/retired-window callbacks. No global monitor, timer, overlay view, responder replacement or runtime class mutation.
- Before each placement, restore public `NSMainMenuWindowLevel + 2` and `CanJoinAllSpaces | FullScreenAuxiliary | Stationary | IgnoresCycle` only when different. Use the shared finite frame predicate before writes, origin correction and readback: accept only an absolute X-origin delta of at most 0.5 logical point, with Y/width/height exactly equal. Accepted quantization never repeats `setFrame`/`setFrameOrigin`; ideal notch-center placement and notch metadata stay unchanged. After a changed frame, correct a remaining unacceptable origin mismatch with public `setFrameOrigin`, then read actual `NSWindow.frame()`; read back again after initial `orderFront`. Diagnostics retain only phase/mode/window/level, requested/actual rects and maxY, `NSScreen.frame.maxY` (not visibleFrame), top deltas, horizontal-origin delta, `requested_exact` and accepted `requested_matched`. Positive screen-minus-actual top gap means below the screen edge. Reject vertical/size mismatches, nonfinite fields and larger X deltas instead of reporting requested placement as successful. Existing move/DPI/focus notifications recheck later displacement without timers. User geometry logs recorded peek requested X=655.5 versus actual X=655.0 with identical Y=942, width=400, height=170 and top gap=0; strict equality rejected this normal horizontal quantization and rolled the view back to compact. Regression tests use that odd-notch geometry without session data. The level is not a proven constraint bypass; pure tests do not establish actual AppKit attachment or hover delivery. Rust changes require a rebuilt/restarted app for product readback.
- Debug builds also overwrite `opencode-mom-island-native-frame.log` in the OS temporary directory with the latest frame readback and PID; it contains only geometry/window metadata, no sessions, messages or credentials. Release builds log only to stderr. Unchanged frames do not create diagnostic file writes.
- Debug tracking diagnostics log only options, native bounds/window flags and boundary view/connection/running count. Never log snapshots, session IDs, paths, messages or credentials. Compilation and mock event tests do not prove actual non-key AppKit delivery; restart the rebuilt app for manual hover acceptance.
- Tauri transparency enables `macOSPrivateApi` for compatibility with older Tauri. The matching Cargo feature is declared on the base dependency because tauri-build validates that table instead of merged target features; it has no non-macOS effect. Not an `NSPanel`: fullscreen Spaces, notch hit testing, focus behavior, display/wake changes need manual acceptance. Reposition on expansion/focus/move/DPI events, not timers; no dedicated wake observer.
- Tests never launch the app, power helper, or live OpenCode API.
