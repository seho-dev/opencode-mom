# Island geometry, motion and window events

Source-relative paths below are relative to `src/routes/island/`, not this docs directory.

## Ownership

Native three-shape notch Island with CSS content motion, a quick permission queue, and lazy sessions in an independent window without global preload. Question responses preserve field keys and option values, using the shared Checkbox for multiselect and a read-only fallback.

## Geometry, density and attention

- **Geometry and compact content**: Keep the continuous #070708 screen-edge backdrop, square top edge and content-free notch safe gap across compact/peek/expanded; never fake a notch with a transparent cutout. Every screen starts/collapses compact; geometry changes density/size, not view/IPC. A notch requires positive `notchWidth` and `topInset` from finite nonnegative backend geometry, never device/user-agent guesses. Compact is max(notchWidth + 112, 200) × max(topInset, 28): left wing shows short state over running count; right shows one 18 px activity visual beside pending count over its label; notch gap stays empty. No-notch compact is 200 × 28 with two text levels: state/running count plus snapshot session count, then separate permission/question counts; the same single activity visual stays right. Counts describe only the bounded snapshot including cached children, not totals/history; connected idle shows zeroes, disabled/connecting/error shows em dashes, never current-looking cached aggregates. Cap visible counts at 99+; both compact buttons expose exact snapshot/request counts accessibly. Default compact excludes branding/extra icons/project titles/paths/request or message text/raw errors. Peek is 400 × (topInset + 132), with 36 px header/96 px body below the safe gap; expanded is 560 × 520. Unknown/invalid geometry stays hidden and cannot request peek; native owns real sizing, never oversized hidden hit areas.

- **Attention and hover**: Compact permission attention needs an enabled connected snapshot across all sessions/children; retain current session/request ID through reorder. Queue/Allow once/Reject never select sessions, expand or read messages. One main hit surface owns enter/move/leave/focus, including exposed center/safe top gap; no racing wing/shell handlers. Hover/focus uses one 100 ms entry timer, pointermove recovers missing entry without restarting; compact click/touch/Enter/Space requests peek only, even without permissions. Preserve header controls through peek for keyboard focus. Peek shows cached status/question hints/body Refresh, never chat/autofocus; only explicit downward Expand sessions click/keyboard activation expands/reads messages, never header/arrow hover. One 180 ms leave timer also covers resize; retain peek while hovered/focused/menu-open/busy/checking replies. Compact click holds peek until leave/blur, without pinning. Never queue duplicate/no-op peek or let late hover override expanded/authoritative collapse; pending arrival never expands. Geometry/status changes never reset view, fetch messages outside expanded, focus or authorize. Local blur follows leave protection; `island:collapsed` wins without cancel/retry writes. Clean all timers/listeners on teardown.

- **Activity visual**: Use system text and one 18 px CSS-only four-bar visual inside the right wing. Idle/disabled/disconnected retain four static low bars, never dot-only status; animate only enabled connected actually-running snapshots. `prefers-reduced-motion` retains a static active wave; add no animation libraries/timers.

## CSS and AppKit frame transitions

- **CSS motion**: Presentation-only CSS fills the real native viewport (`100vw` × `100dvh`) with black, square top/content-free camera gap; never move/scale/fade the whole backdrop or tween width/height. Content enters from opacity 0.72 and 4 px below rest over 180 ms, or 220 ms for session list/conversation, using `cubic-bezier(0.22, 1, 0.36, 1)` without delay. Transition header heights/lane sizing/lower radii/selected-row colors without replacing compact/peek header buttons or activity DOM. Permission identity/conversation changes use immediate keyed replacement, no outro/hidden retained controls/duplicate approval buttons/animation callbacks. Keep composer mounted through selection; motion never chooses view, focuses, reads or acts.

- **Native frame motion**: Main-thread `NSAnimationContext` + `NSWindow.animator()` grows changed sizes in 220 ms, shrinks in 190 ms around the existing top/notch-center anchor. Final correction/readback precedes geometry/view commit, eligible explicit expanded focus and async IPC success; lowercase enum-to-void wire stays unchanged. Frontend keeps authoritative old view during grow and mounts/animates target content only after IPC success. Native compact/blur/close clears selection and emits `island:collapsed` before shrink; frontend immediately removes peek/expanded controls/focus nodes without outro and invalidates late results. Compact remains authoritative even if shrink fails, never restoring controls; actual intermediate bounds own hover/hit testing, not a permanently expanded transparent area.

- **Transition ownership**: Native keeps one active/latest pending request guarded by generation/serial/window identity; superseded animation finishes without commit/focus. Reversal waits only remaining animation (approximately 220 ms max), then its own transition, never immediate retarget. Frontend sends compact immediately during pending grow/peek, deduplicates pending targets and accepts latest request identity/version only; stale grow cannot restore controls/read messages. The first early `island:collapsed` acknowledges its compact request while retaining genuine final-readback errors; later collapse/new request/teardown invalidates them. Failed shrink stays compact, reports via status-control title and never auto-retries. Changed/SSE only updates content; display/DPI placement reconciles instantly after active motion. Startup/unchanged/position-only/placement/error-correction/native reduced-motion paths are instant. CSS reduced-motion cancels new CSS motion at runtime; native independently samples `NSWorkspace.accessibilityDisplayShouldReduceMotion()` per transition without watcher, so running animation may finish. Never delay collapse/control removal for animation.

## Window events and manual acceptance

- **Listeners and reads**: Register window-targeted `island:changed`, `island:collapsed`, `island:pointer-enter`, `island:pointer-leave`, `app:preferences-changed` before initial snapshot. Void pointer events only update native hover, never focus/expand/read/mutate. Separate DOM/native booleans combine presence: either retains peek, duplicate entry never restarts the 100 ms deadline, only both leaving starts protected 180 ms shrink; DOM pointermove recovers entry. Expanded ignores hover; disabled snapshots/authoritative collapse/teardown clear both flags/timers, and stale peek readback cannot revive view. Native delivery proves no physical camera/notch hover. Dispose late listener registrations; invalidations use one bounded 200 ms timer and serialized dirty reads, never polling/per-token requests.

- **Manual acceptance**: Source/jsdom cannot prove AppKit/WebKit smoothness, native focus timing, viewport repaint, attachment, seams, actual bounds or physical camera hover. Grow may expose black while old view remains; immediate compact centers in the shrinking viewport. Verify rebuilt apps on notched/non-notched screens, rapid reversal, keyboard/blur collapse, runtime Reduce Motion and display changes; tests never imply manual acceptance.

## Route integration

- **Island mode**: `/island` bypasses `AppShell`/`SplashScreen` and global preload; every screen starts/collapses compact, with notch geometry changing density, not view. Non-notched compact adds short status/count text beside the same single indicator. Before initial snapshot, register only native-targeted `island:changed`, `island:collapsed`, `island:pointer-enter`, `island:pointer-leave`, and `app:preferences-changed`. Void pointer events update separate native hover alongside DOM hover via shared 100 ms entry/180 ms protected leave timers, never focus/expand/read/mutate. Expanded ignores hover; disable/collapse/teardown clear both sources. Coalesce reads, fetch messages only expanded, and clean listeners/timers/late registrations.

- **Island motion**: Native `NSAnimationContext`/`NSWindow.animator()` grows changed frames in 220 ms and shrinks in 190 ms; correction/readback precedes grow view/focus/IPC success. Frontend immediately sends compact during pending grow, deduplicates targets and guards latest-request results. Native compact/blur/close emits authoritative collapse before shrink, removing controls without outro; the same compact request retains final shrink errors without restoring controls/retrying. One active/latest pending native request waits only remaining current animation (approximately 220 ms maximum), not total reversal duration. CSS fills real intermediate bounds with the unmoving black screen-edge backdrop; target content mounts only after grow IPC success, entering in 180–220 ms while preserving peek-header focus/immediate keyed replacement. CSS reduced-motion reacts at runtime independently of OS reduced-motion sampled per native transition; startup/placement/correction are instant. Rebuilt-app manual acceptance must verify bounds/seams/focus/physical camera gap/smoothness.
